## 租户相关问题

### 问题背景——训练作业任务列表 查看权限

客户新建了一个账号，并分配了权限。但该账号登录后，能看到平台上**所有用户**创建的训练作业。客户期望的效果是：**一个账户只能看到自己创建的训练作业，无法看到其他人的**，实现训练任务的隔离。

#### 问题原因分析

1. **权限过高**：该账号（或所属用户组）被授予了过高权限（如 `ModelArts FullAccess` 等），导致拥有全局查询权限
2. **工作空间类型不当**：ModelArts 默认的工作空间为 `PUBLIC` 类型，租户内所有用户均可看见其中的资源
3. **缺少资源隔离机制**：没有通过工作空间（Workspace）将不同用户的资源进行逻辑隔离


#### 解决方案：IAM 权限 + 工作空间（Workspace）组合

ModelArts 的权限隔离由 **IAM（统一身份认证）** 和 **工作空间（Workspace）** 共同实现，两者叠加生效。


##### 一、IAM 权限：控制“能做什么”

IAM 权限用于控制用户对云服务资源的操作范围，如创建、查看、删除等。

| 权限策略 | 说明 |
|---|---|
| `modelarts:trainJob:create` | 允许创建训练作业 |
| `modelarts:trainJob:list` | 允许列出训练作业 |
| `modelarts:trainJob:get` | 允许查看作业详情 |
| `modelarts:workspace:get` | 允许访问指定工作空间 |

**⚠️ 注意**：仅靠 IAM 权限难以实现“只能看自己的”这一效果，因为 `list` 类权限通常是租户级别的。


##### 二、工作空间（Workspace）：划定“能看到什么”

工作空间是 ModelArts 提供的**资源逻辑隔离**功能，类似一个“项目文件夹”或“办公区”。

**工作空间访问类型**：

| 类型 | 说明 | 适用场景 |
|---|---|---|
| `PUBLIC` | 租户内所有用户可见 | 公共资源、共享项目 |
| `PRIVATE` | 仅创建者、管理员和指定成员可见 | **个人专属隔离** |
| `INTERNAL` | 创建者、管理员及指定用户或用户组可见 | 团队协作 |

**操作建议**：
- 为**每个需要隔离的用户**（或用户组）创建一个**独立的 `PRIVATE` 工作空间**
- 将用户添加为工作空间的唯一成员
- 用户登录后，只能看到自己有权限访问的工作空间，也就只能看到该空间下的训练作业


#### 推荐操作步骤

**第一步**：梳理用户角色和职责范围（管理员、开发者、只读用户等）

**第二步**：为每个用户（或团队）创建独立的 `PRIVATE` 工作空间

**第三步**：配置对应的 IAM 权限，确保：
- 用户拥有访问工作空间的权限（`modelarts:workspace:get`）
- 用户在工作空间内拥有执行操作（如创建、查看训练作业）的权限
- **移除**用户不必要的全局 `list` 权限

**第四步**：测试验证，使用不同账号登录，确认只能看到自己被授权的工作空间及其资源


#### 给客户的解释话术

> “您提到的问题，是典型的多租户权限管理需求。ModelArts 提供了‘工作空间’功能来解决。
>
> 您可以把它理解为在平台上为每个用户或团队划分一个**独立的‘办公区’**。默认情况下，所有用户都在一个公共区，所以能看到彼此。我们可以为每个用户创建一个**仅自己可见（`PRIVATE`）** 的‘办公区’，并配合配置好 IAM 权限。
>
> 这样，用户登录后，就只能看到并操作自己‘办公区’里的训练作业，实现了完全的隔离。这既保障了数据安全，也让管理更清晰。”


#### 关键点总结

| 关键点 | 说明 |
|---|---|
| 根本原因 | 账号权限过高 + 未配置工作空间隔离 |
| 核心机制 | IAM 权限控制 + 工作空间逻辑隔离 |
| 工作空间类型 | 用 `PRIVATE` 实现个人隔离，`INTERNAL` 实现团队隔离 |
| 操作要点 | 为每个用户建独立工作空间，并移除不必要的全局权限 |
| 最终目标 | 用户只能看到自己工作空间内的训练作业，无法看见或操作他人的 |
