## ⚠️注意

目前，部分大模型的算子对昇腾NPU的Snt9b算力切分卡支持不完整，因此在某些场景下，这些模型无法在vNPU切分卡上成功运行。

需要特别说明的是，ModelArts提供了算力切分的资源管理与调度能力，其本身并不改变NPU硬件对算子的执行支持能力。是否能在切分卡上成功运行模型，最终取决于昇腾NPU硬件对相关算子的支持情况。

如果您已自行验证其模型能够在算力切分卡上正常运行时，则可尝试使用ModelArts的算力切分功能，相关调度问题可以联系ModelArts的技术支持协助定位。然而，对于因算子不支持导致的切分卡执行失败类问题，属于硬件兼容性问题，ModelArts无法提供解决方案。

因此，建议在未确认模型兼容性前，谨慎使用算力切分卡部署，以避免运行失败。

这个 `npu-smi info -t template-info` 命令，显示的是 **NPU 算力切分可用的虚拟化模板**。简单说，它告诉你当前这台昇腾服务器支持把一块物理 NPU 切成什么样的“小号虚拟卡”。

输出里有两个模板：**`vir12_3c_32g`** 和 **`vir06_1c_16g`**。我们以 `vir12_3c_32g` 为例拆解一下：

| 字段               | 值              | 含义                                      |
| ---------------- | -------------- | --------------------------------------- |
| **Name**         | `vir12_3c_32g` | 模板名，通常表示**12个AI Core / 3个CPU / 32GB显存** |
| **AICORE**       | 12             | 分配的 AI Core 数量，决定了算力高低                  |
| **Memory**       | 32 GB          | 分配的 HBM 显存大小                            |
| **AICPU**        | 3              | 分配的 AI CPU 数量，负责任务调度控制                  |
| **VPC**          | 5              | 视频/图像预处理引擎（Video Process Controller）    |
| **VENC**         | 0              | 视频编码器，此处表示该模板**不分配**视频编码能力              |
| **JPEGD**        | 14             | JPEG 硬件解码器个数                            |
| *(第二行)* **PNGD** | 0              | PNG 硬件解码器个数，0 表示不分配                     |
| **VDEC**         | 1              | 视频解码器个数                                 |
| **JPEGE**        | 2              | JPEG 硬件编码器个数                            |

模板 `vir06_1c_16g` 同理：6个AI Core，1个AI CPU，16 GB显存，配套更少的媒体处理引擎。

### 这和你的专属资源池有什么关系？

结合你之前问的 **算力切分必须安装 modelarts-device-plugin ≥1.2.0**，这个输出正好印证了：
1.  **驱动与固件支持**：你的节点已具备昇腾虚拟化能力，驱动层面提供了模板切分功能。
2.  **与 ModelArts 对接**：创建专属资源池并启用算力切分时，ModelArts 的插件（`modelarts-device-plugin`）会扫描这些模板，并将它们映射成 Kubernetes 可调度的资源。在创建任务时，你就可以指定需要的 vNPU 规格，比如 `huawei.com/ascend-310-12c`（名称可能对应 `vir12_3c_32g`）。

**两个关键点：**
- 这些模板是**只读**的，由固件预定义，用户无法自行修改（除非刷入其他固件）。
- 物理芯片的总资源是固定的，一块卡能切出多少个虚拟卡，取决于你选择的模板。比如一块拥有 48 AI Core / 96GB 显存的物理卡，理论上可以切分出 4 个 `vir12_3c_32g` 实例。

如果你是想在 ModelArts 专属资源池里配置算力切分，现在这个节点状态说明硬件侧已准备就绪，接下来只需确保插件版本≥1.2.0 并正确启用切分即可。
